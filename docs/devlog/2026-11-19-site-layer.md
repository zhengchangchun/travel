## 三、账号与会话（真登录）
- `users`：`username`（唯一、忽略大小写）、`password_hash` + `salt`（**scrypt**，N=16384 r=8 p=1 keylen=64）、昵称头像、默认城市与出行方式。
- `sessions`：令牌是 32 字节随机串，**库里只存 sha256**；Cookie 为 `travel_session`（HttpOnly、SameSite=Lax、30 天）。
- 防枚举：账号不存在与密码错给同一句文案。头像只收 `http(s)` 或 `data:image`。

## 四、按用户隔离
- `trips.user_id` / `shares.user_id` / `notes.user_id`；点位通过行程归属。
- 未登录 → `401 AUTH_REQUIRED`；别人的行程/点位/笔记/分享 → `404`（不泄露「有这条」）。
- 账号上线前的行 `user_id` 为空 ⇒ 谁都看不到；`/api/legacy/pending` 报数量、`/api/legacy/claim` 一键认领（行程 / 分享 / 笔记），「我的行程」页有提示与按钮。
- 测试里给老用例留了 `createApp({ authFallbackUser: true })`（**只给测试**，生产不设），新的隔离用例故意不开它。

## 五、一城多趟
- 规划页行程卡加「当前一趟」下拉；选中 / 拖拽排序 / 删点 / 导出 / 逐段规划全部认 `tripId`（不带才回退该城第一趟，老链接不坏）。

## 六、按天分段
- `pins.day`（默认 1，就地迁移）；清单按天分组「第 N 天 · k 个点 · 直线 ≈ x km」，每行 **D- / D+** 挪天（1–30 夹紧）。
- 排序＝先按天再按「按距离/手动」，天内相对顺序稳定（修过：纯按距离排会把天交错、分隔行重复）。
- 导出 Markdown 与分享包都按天分段，序号跨天连续；**只有一天时输出与以前完全一致**（老行为不破）。

## 九、顺手修的真 bug（都是实测撞出来的）
1. 静态地图封面把「坐标缺失（null）」当成 `0,0`，取景拉到整张世界地图（杭州两日封面成了欧洲+非洲）。
2. 封面 `max-age=86400` 导致换图后仍看旧图 ⇒ 改 `no-cache`。
3. `mapPin` 漏了 `day`，点 D+ 库改了页面不动。
4. `orderedPins()` 纯按距离排 ⇒ 按天分组时天交错、分隔行重复。
5. 行程清单一行塞了 4 个小按钮 ⇒ 名字被挤成竖排（允许换行 + 给名字最小宽度）。
6. `site.css` 的 `.card/.row` 与规划页 `style.css` 撞车 ⇒ 站点样式统一加 `body.site` 前缀。
7. 许可正则按「CC BY-SA」连字符写，实际短名是「CC BY-SA 4.0」（空格）⇒ 所有图被拒，白跑几轮。
