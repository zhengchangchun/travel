## 改法

| 处 | 之前 | 之后 |
| --- | --- | --- |
| 右侧「我的选择」 | 只有「定位 / 移除」两个按钮，点「规划行程」才排线 | 每项带 **序号 ①②③**、**上一站到这里的耗时**（`28 分 · 13.0 km`）、**↑ ↓ 调顺序**（落库）、定位、移除 |
| 汇总行 | 无 | 列表上方一行：**出行方式 + 总用时 + 总里程 + 段数**，右侧「驾车 / 步行 / 公交」三个 chip 现场切换 |
| 计算时机 | 必须手点「规划行程」 | 选中 / 取消 / 换顺序 / 换方式任一变化 → **防抖 700ms 自动重算** |

实现（`web/js/quickroute.js` 纯计算 + `app.js` 接线）：
- **先给估的、再给真的**：立刻用「直线距离 × 绕行系数 ÷ 平均速度」出一版（带 `≈`），界面不用等网络；
  服务端 `/api/itinerary/route` 回来后再替换成实测值（去掉 `≈`），哪段没算出来就保留估算并说明「N 段按直线估算」。
- 参数：驾车 绕行 1.35 / 26 km·h⁻¹，步行 1.18 / 4.8，公交 1.55 / 16（只用于估算）。
- **不重复打接口**：签名 `城市|方式|点序列` 记在 `state.liveKey`，一样就直接返回（`refresh()` 会在很多场合调
  `renderSelection()`，没这个守卫会打爆接口）。
- 顺序调整走既有的 `Selection.move(index, delta)`（服务端 `sort_order` 落库），所以「规划行程 / 自动成线」看到的是同一份顺序。
