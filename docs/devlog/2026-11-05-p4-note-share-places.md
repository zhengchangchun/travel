## 做了什么

1. **服务端解析层**（新 `server/note-share.js`，纯函数）
   - `parseShareText`：从 App 分享文案里拆平台/形态/标题/作者/链接。
     抖音走「看看【X的作品】标题」、小红书走「标题 - 小红书」、快手/抖音标题常挂在链接后面走「【标题】」。
   - `extractUrl`：链接后面直接跟中文（分享文案常见）也能截干净。
   - `cleanContent`：给页面的正文初值 —— 去链接、去引导语（复制打开抖音/复制本条信息/打开【小红书】App…）、
     去标题与作者、去「看看【X的作品】」残渣、去行首播放量数字、去只剩平台名的行。
   - `extractPlaceNames`：话题标签/链接/@/emoji 先剔除 → 按标点切段 → 段内再按地名特征词贪婪切
     （「晚上去河坊街」→「河坊街」、「停车可以停在涌金广场」→「涌金广场」）→ 去泛词、去重保序、上限 12。
2. **库**：`notes` 加 `kind/video_url/share_text`；新表 `note_places`（含 `poi_name`，供「加入选择/地图」用真名）。
3. **路由**：`/api/notes/parse`、`GET /api/notes/:id`、`POST /api/notes/:id/places`（`resolve=1` 才打高德，
   逐名 1 次、最多 8 个、失败不写假点）；`POST /api/notes` 支持 share_text/kind/video_url/cover_url，url 不再必填。
4. **页面**：左栏「笔记 → 找地方」卡片：粘贴（自动识别）→ 可改 → 存本地 → 列表（来源/形态/地点数）
   → 详情（封面/正文/图条/原链接 + 提取地名 + 高德补全 + 地名可编辑 + 每点「加入选择」「地图」）。

## 踩到的坑

- **分享文案里的链接后面没有空格**，直接跟中文 ⇒ 正则要把汉字也当 URL 终止符，否则一整串中文都被吃进 URL。
- **地名抽取的贪婪前缀**：`{1,10}` 会把「晚上去」「停车可以停在」一起吞掉 ⇒ 加「连接字」从最后一次出现处切开。
- **话题标签**：`#[^#\n]{1,30}#?` 会把下一个标签的前导 `#` 吃掉，导致「咖啡地图」这类残段漏出来 ⇒ 改成 `#[^#\s]{1,30}`。
- **`url` 必填放宽后**，旧用例「缺 url → 400」要跟着改成「url/share_text/title 全空才 400」。
- **验收时删了 `dev.db` 又没杀掉旧进程**：旧进程握着已 unlink 的文件，写入报
  `attempt to write a readonly database`（看着像权限问题，其实是「文件被换掉」）⇒ 先 `/usr/sbin/lsof -ti tcp:<port> | xargs kill` 再换库。
- 页面「地图」按钮点完状态栏会被随后的视野加载文案覆盖 ⇒ 相机是否真落到位要用 `TravelMap.getBounds()` 量，别读状态栏。
