# devlog 2026-11-05 · P6 地名补全兜底（OSM）

## 起因

「按笔记搜地方」的最后一跳（笔记地名 → 地图上的点）一直没在**真数据**下跑通过：
高德搜索配额本月已耗尽（`USER_DAILY_QUERY_OVER_LIMIT`），P4 那轮只能用假高德验。

## 摸底（都实测过）

| 兜底源 | 结果 |
|---|---|
| Nominatim（OSM 官方） | **连不上**（curl 000） |
| **Photon（komoot）** | **200 可用**，`q=西湖` 返回 `120.1431,30.246` 等真实坐标 |
| 天地图（无 key） | 418（CloudWAF 拦） |

⇒ 用 Photon。它是公共免费服务，所以按 1.1s 间隔、单次 ≤8 个名字用。

## 做什么

1. `server/geocode-osm.js`：结果归一成与高德同形状（`id=osm:type+id`、`source='osm'`、**没有评分就不编**）。
2. 路由里「高德 → OSM」两级：高德抛错/无果才走兜底；`by_source` / `osm_calls` 如实分列。
3. `note_places.source` 列 + 界面 `OSM` 角标（来源不许混）。
4. **同名才认**（`matchesName`）：实测 OSM 会把「1% COFFEE」配成「环城东路」、「COFFEE」配成「九龙大道」；
   旅行场景里**错点比没点更坏** ⇒ 只认同名（归一后相等/互相包含、长度 ≥2），否则报「没有同名地点」。
5. 顺手修的真 bug：地名输入按空白切分 ⇒「1% COFFEE 精选店」被切成 `1%`、`COFFEE`、`精选店` 三段
   （这也是上面那两个离谱匹配的直接原因）；改成只按顿号/逗号/换行切。
6. 抖音「按关键词搜」补一句实话：实测搜索页是**验证码中间页** ⇒ 返回 `NEED_CAPTCHA`，
   文案写明「抖音只能给链接抓单条」。

## 读数

- 全量单测 **331 passed / 0 fail**（P5 基线 324）。
- 真数据端到端：搜「杭州咖啡」→ 抓详情 → 地名「西湖、灵隐寺、缓奏咖啡店」
  ⇒ 高德 3 次（配额用尽全失败）· OSM 兜底 3 次 · 补全成功 2 个（西湖/灵隐寺，标 OSM）、
  缓奏咖啡店如实未补全；「地图」相机实测落到 `120.1431,30.246 zoom16`；加入选择 1 条。
