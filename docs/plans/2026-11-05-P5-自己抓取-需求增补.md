## 1. 结论：能抓，但要借本机浏览器 + 已登录 profile

平台网页的接口都带**页面 JS 现算的签名**（抖音 `a_bogus`、小红书 `x-s`），Node 里伪造不了；
但**浏览器里由平台自己的 JS 发请求**就一切正常 ⇒ 抓取器的做法：
**让页面自己去加载，我们只拦它自己的接口响应 / 读它挂在 `window` 上的状态，再归一化。**

本机已有登录好的浏览器 profile：`~/.nanobot/workspace/.browser/{xhs,douyin,kuaishou}`。

## 3. 落地

**抓取器**（仓内 `tools/note-fetch.cjs`，由本机 Playwright 加载运行）
- `search <platform> <keyword> <limit>` / `url <platform> <url>` 两种模式，stdout 一行 JSON。
- 所有页面打开都带 60s 超时 + 失败重试一次（同一 profile 被别的进程占着时会瞬挂）。
- 失败形状统一：`BAD_PLATFORM / NEED_LOGIN / NO_DATA / FETCH_FAIL / TIMEOUT / NOT_IMPLEMENTED / BAD_REQUEST`，**一句人话**。

**服务端**（`server/note-fetch.js`）
- 拼命令 → 跑 `/opt/homebrew/bin/node <pw.cjs> run <note-fetch.cjs> …`（绝对路径，不走登录 shell）→ 解析最后一行 JSON。
- `fetchNote({url})`：小红书/抖音/快手走浏览器；B站走官方接口；失败自动重试一次（只对 TIMEOUT/FETCH_FAIL）。
- `searchNotes({platform, keyword, limit})`。
- 依赖注入：`createApp({noteFetch})` ⇒ 测试里换成假抓取器，**单测不起浏览器**。

**路由**
- `POST /api/notes/fetch`：给 `url` 或整段分享文案（自动取链接）→ 抓 → 图/封面下本地 → 默认只返回预览（`save=0`），`save=1` 落库；**同链接已存在则更新**（不重复入库）。
- `POST /api/notes/discover`：按关键词搜一批候选；**封面也下到本地**（否则页面直连平台 CDN 会 403），标出 `exists`（已在本地库）；不写库。
- `POST /api/notes/:id/refresh`：用库里链接重抓，覆盖正文/图。
- 抓回来的标题/正文过一遍 `tidyText`（去链接、去「复制此链接，打开抖音搜索…」这类平台自带话术）。

**页面**（左栏「笔记 → 找地方」）
- 「抓取」：粘链接/分享文案 → 一键抓 → 落库落图 → 自动提地名 → 打开详情。
- 「搜笔记」：关键词 + 平台（小红书/抖音/快手）→ 候选列表（本地封面/标题/作者/点赞）→ 「存到本地」抓详情。
- 详情加「重抓」按钮；手动贴正文降级进 `<details>` 备用。

## 5. 边界与代价（对用户明说）

- **依赖本机已登录的浏览器 profile**：登录过期会报「可能需要重新扫码登录」，此时重扫一次即可。
