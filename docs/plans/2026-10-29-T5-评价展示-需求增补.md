# T5 需求增补：评价展示（用户实拍图 · 招牌菜 · 去高德看评价）

> 2026-10-29 · 依据用户原话：「可以按照分进行过滤，然后可以**看好评**」
> 前置：T4（POI 取全 · 分类纯净 · 评分色阶 · 评分过滤）已交付 —— **T5 依赖 T4 落库的 `photos` / `tags` 字段**。

---

## §0 背景与实测结论

用户要「看好评」。**先说清楚能拿到什么**（2026-10-29 实测）：

| 想看的东西 | 能不能 | 证据 |
|---|---|---|
| 评分 | ✅ | `biz_ext.rating` |
| 人均 | ✅ | `biz_ext.cost` |
| **用户实拍图** | ✅ | `photos[]` 里有 `aos-comment.amap.com` 域的**评论图** —— 实测 10 个餐饮 POI 共 30 张图，**17 张是评论实拍图** |
| **招牌菜 / 标签** | ✅ | `atag` / `tag`，如「虎皮凤爪,椒麻大虾,渣渣牛肉锅…」 |
| 评价 **文本** | ❌ | `featured_reviews` / `featured_reviews_remake` **恒为空数组**（杭州美食 20 条 + 杭州酒店 20 条 + 杭州景点 20 条 + 上海美食 20 条，**全部 0 条**）；`place/detail` 同样为空 |
| 跳过去看真实评价 | ✅ | `https://www.amap.com/detail/<poi_id>` 实测 **HTTP 200**（`/place/` 是 302） |

**结论**：高德不给评价文本，所以「看好评」的实际做法是 ——
**把能拿到的（评分 + 用户实拍图 + 招牌菜标签）做成一个像样的详情面板，再给一个「去高德看评价」的直达按钮。**

---

## §1 功能（本期做）

| 编号 | 功能 | 说明 |
|---|---|---|
| **K1** | **详情面板** | 点列表项/地图旗子 → 侧栏展开或弹层：大图 + 名称 + 分类 + 详细地址 + 评分/人均/电话/营业时间 |
| **K2** | **用户实拍图集** | 把 `photos` 里全部图片做成可左右翻的图集，**评论实拍图优先展示**（打「用户实拍」角标） |
| **K3** | **招牌菜标签** | 把 `atag` 渲染成一排标签 chip（如「虎皮凤爪」「椒麻大虾」） |
| **K4** | **去高德看评价** | 一个明显按钮 → 新窗口打开 `https://www.amap.com/detail/<poi_id>`（提示「真实评价在高德」） |
| **K5** | **满分徽章** | 沿用 T4 的满分金色标识，详情面板里也显示 |

---

## §2 交互

```
列表项 / 地图旗子 → 点开详情面板
  ├─ 图集（评论实拍图优先，标「用户实拍」；左右翻）
  ├─ 评分 ★4.7 · ¥172 · 营业中
  ├─ 详细地址（可复制）
  ├─ 招牌菜标签：[虎皮凤爪] [椒麻大虾] [渣渣牛肉锅] …
  ├─ 电话（可点拨打）
  └─ [导航] [去高德看评价] [去小红书看笔记] [加入行程 ★]
```

**诚实标注**：面板里要有一句小字说明「高德接口不提供评价正文，点上方按钮去高德看真实评价」——
避免用户以为我们藏了数据。

---

## §3 接口契约

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/pois/:poiId` | 单点详情：`{poi_id,name,category,address,lng,lat,rating,cost,tel,opentime,photos:[…],tags:[…],amapUrl}` |

- `photos` 每项形如 `{url, isComment:true|false, source:"amap"}`（`isComment` 由 url 含 `aos-comment` 判定）
- `amapUrl` 由后端拼 `https://www.amap.com/detail/<poi_id>`（**不让前端拼**，方便日后换域）
- 缓存表里没有该 poi → `404`

- 其余模块不受影响
