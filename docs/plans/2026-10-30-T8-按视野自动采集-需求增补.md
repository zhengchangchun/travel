# T8 需求增补：按视野自动采集（渐进加载）

> 2026-10-30 · 依据用户原话：「**数据采集应该是默认的行为**，就是**地图大的时候才慢慢加载，地图小的时候是不加载的**」
> 前置：T7（视野加载 + 倍率门控）已交付。

---

## §0 背景

现在采集是**手动**的（要点「开始采集」按钮，一次采全城 ≈400 次高德调用）。
用户认为这不合理，采集应该是**默认自动**的，且**跟地图比例挂钩**：

```
地图放大到一定程度（zoom ≥ 阈值） → 自动采集当前视野里【还没采过】的格子，点慢慢出现
地图缩小（zoom < 阈值）           → 不采集、不加载（只提示「放大地图以加载」）
```

这样：配额花在"用户真正在看的地方"，而不是一上来就把整城采完。

---

## §1 功能

| 编号 | 功能 | 说明 |
|---|---|---|
| **N1** | **自动采集为默认** | 不再要求点按钮。`zoom ≥ MIN_COLLECT_ZOOM`（默认 **13**）时自动检查当前视野 |
| **N2** | **覆盖记录（网格）** | 以固定网格（默认 **0.01°×0.01°**，约 1km）记录「该格已采过」；存库，重启不丢 |
| **N3** | **只采没采过的** | 视野内取未覆盖的格 → 触发采集（后端按 bbox 用周边/多边形搜索）→ 落库 → 标记覆盖 |
| **N4** | **渐进加载** | 采集是异步的：**先显示已有数据**，采到的**逐步补上**；全程不许白屏等待；显示「本区域加载中…」 |
| **N5** | **缩小时不采集** | `zoom < MIN_COLLECT_ZOOM` → **不触发任何采集**、不加载点，只提示「放大地图以加载本区域」 |
| **N6** | **节流与配额保护** | ① 同一格不重复采；② 单位时间采集调用数上限（默认 60 次/分钟）；③ 一轮采集进行中不叠加新轮（可排队但合并同格） |
| **N7** | **手动「采集全城」保留** | 作为补全手段（用户想一次采全时仍可用），但**不再是默认路径** |

## §2 数据模型（新增）

```sql
-- 采集覆盖格（幂等迁移）
CREATE TABLE IF NOT EXISTS poi_coverage (
  city       TEXT NOT NULL,
  category   TEXT NOT NULL,          -- 分类 key；'all' 表示不限分类
  gx         INTEGER NOT NULL,       -- lng 网格号（floor(lng / GRID)）
  gy         INTEGER NOT NULL,       -- lat 网格号
  collected_at TEXT NOT NULL,
  n_inserted INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (city, category, gx, gy)
);
```

- 网格大小常量 `GRID_DEG`（默认 `0.01`）
- 「已覆盖」判定：`(city, category, gx, gy)` 存在即可

---

## §3 接口（新增/扩展）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/coverage?city=&bbox=&category=` | 返回该 bbox 内**未覆盖**的格列表（前端据此决定要不要采） |
| POST | `/api/collect/viewport` | `{city, bbox, category}` → **只采未覆盖的格**，异步；返回 `{runId, grids:[…]}`；同一格已在跑 → 合并，不重复 |
| GET | `/api/collect` 既有接口 | 保留（全城采集，手动用） |

- `/api/collect/viewport` 对已是覆盖的格**直接跳过**（不产生高德调用）
- 返回值里的 `runId` 可复用既有的 `/api/collect/status` 轮询

## §4 前端流程

```
地图 moveend / zoomend（防抖 300ms）
  ├─ zoom < MIN_COLLECT_ZOOM  → 清点、显示「放大地图以加载本区域地点」，结束
  └─ zoom ≥ MIN_COLLECT_ZOOM
       ├─ 先按 T7 的 bbox 读缓存 → 立即落旗（有多少画多少）
       ├─ GET /api/coverage?city=&bbox=&category= → 有未覆盖的格？
       │     ├─ 有 → POST /api/collect/viewport（自动，无需点按钮）
       │     │        → 显示「本区域加载中…」
       │     │        → 轮询/等待完成后，重读 bbox 缓存 → 增量补旗
       │     └─ 无 → 结束（已是最全）
```

- **渐进**：不要等采集完成才画，先画已有的
- 采集中的格子要**去重**（防抖 + 前端记录"正在采的格"）

## §5 不做

- ❌ 后台常驻爬全城（配额不可控）
- ❌ 多城市并行采集
- ❌ 采集任务队列的持久化调度（一轮内存内即可）
