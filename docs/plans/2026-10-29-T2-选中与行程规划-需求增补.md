# T2 需求增补：选中 · 我的选择 · 只看选中 · 行程规划

> 2026-10-29 · 依据用户原话：「现在继续完善…我需要根据我的选中能够过滤，目前我选中了哪些，然后开始规划我的行程」
> 本文是 T1 需求文档的增补，冲突处以本文为准。基础需求见 `2026-10-29-城市旅行规划器-需求与设计.md`。

---

## §0 背景

T1 交付后，页面能看、能按分类过滤、能落旗、能看到详细地址。

但用户指出缺一条**主线**：现在只能"看"和"按分类筛"，**不能"挑"**。
用户要的是：**挑出想去的地方（选中）→ 看清自己挑了哪些 → 只看自己挑的 → 据此排出行程**。

即：从「浏览工具」升级为「决策工具」。

---

## §1 功能（本期做）

| 编号 | 功能 | 说明 |
|---|---|---|
| **G1** | **选中 / 取消** | 每个地点（结果列表项 + 地图信息卡）有 ★ 选中按钮。点一下选中，再点取消。**无需先建行程**，后台自动归集 |
| **G2** | **我的选择面板** | 左侧新增「我的选择 (N)」区块：列出已选点（名称 + 分类色点 + 详细地址），可点击定位、可一键移除 |
| **G3** | **只看我选中的** | 一个开关。开启后，**地图小旗与主列表只显示已选点**；关闭恢复全部 |
| **G4** | **选中态可视** | 列表项与地图小旗都要能一眼看出"这个我选过了"（★ 高亮 + 旗子加选中样式） |
| **G5** | **规划行程** | 「规划行程」按钮 → 行程视图：已选点按顺序列出，可**上移/下移**调整顺序，**顺序持久化** |
| **G6** | **行程单导出** | 一键复制 / 下载 Markdown 行程单（按顺序 + 分类分组 + 详细地址 + 评分人均） |
| **G7** | 修 T1 遗留 | 底部状态栏计数不随过滤刷新（T1 §8.3-3） |

### 交互主线（验收要照着走）

```
选城市 → 浏览列表/地图 → 点 ★ 选中若干点
   → 左侧「我的选择 (N)」看到我挑了哪些
   → 开「只看我选中的」→ 地图只剩我挑的点
   → 点「规划行程」→ 调整顺序 → 导出/复制行程单
```

## §2 数据模型增补

复用 T1 的 `trips` / `pins`，只增一列 + 一条自动管理规则。

```sql
-- pins 增列（幂等迁移：先查 pragma table_info，缺列才 ALTER）
ALTER TABLE pins ADD COLUMN sort_order INTEGER NOT NULL DEFAULT 0;

CREATE INDEX IF NOT EXISTS idx_pins_poi ON pins(poi_id);
```

**默认行程自动管理**：一个城市一个「我的行程」。用户点 ★ 时若该城市还没有行程，
后端**自动建一个**（`trips.title = '<城市> · 我的行程'`），之后所有选中都挂到它下面。
用户不需要理解"行程"这个概念就能直接用。

**幂等**：同一 `(城市, poi_id)` 重复选中 = 不重复插入（返回已存在的那条）。

## §3 接口契约（在 T1 基础上新增/扩展）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/selection?city=<城市>` | 我的选择：`{tripId, title, pins:[…按 sort_order 升序…], count}`；无行程则 `{tripId:null, pins:[], count:0}` |
| POST | `/api/selection` | 选中 `{city, poi:{id,name,address,lng,lat,category?,rating?,cost?,tel?,photo?}}`；幂等；自动建行程 |
| DELETE | `/api/selection?city=&poi_id=` | 取消选中（前端只知 poi_id） |
| PUT | `/api/selection/order` | 排序 `{city, poi_ids:[…]}` → 按数组下标写 `sort_order` |
| GET | `/api/selection/export?city=&format=md` | 行程单（Markdown 文本，`text/markdown`；供下载，前端也可自行拼接） |
| PATCH | `/api/pins/:id` | 改备注 `{note}`（保留 T1 能力） |

T1 已有接口全部保持**向后兼容**（`POST /api/pins` 仍可用；`trip_id` 变为可选）。

## §4 交互与视觉

- **★ 按钮**：结果列表项右侧、信息卡右上；未选中＝空心星，已选中＝实心星 + 分类色
- **地图小旗选中态**：已选中的旗子加白边/放大/加 ★，与未选中的明显区分
- **我的选择面板**：显示数量徽标；每项「定位 / 移除」；空态给一句引导（"点列表里的 ★ 把想去的地方挑出来"）
- **只看我选中的**：开关式 chip，与分类 chip 同一行或紧邻；**可与分类过滤叠加**（先选分类再叠加"只看选中"）
- **行程视图**：右侧地图不变，左侧切成行程列表；每行有 ↑ ↓ 序号，可长按/拖拽（**最低要求：上下移按钮**）
- **行程单**：Markdown 形如
  ```
  # 杭州 · 我的行程（6 个地点）
  ## 美食
  1. 牛New寿喜烧(来福士店) — 新业路228号杭州来福士广场4楼（★4.7 · ¥172）
  ## 景点
  3. 雷峰塔 — …
  ```

## §5 本期不做（明确排除）

- ❌ **路线连线 / 里程 / 耗时 / 导航路径**（高德路径规划 API）—— 用户尚未确认是否需要，留 T3
- ❌ 按天分日排期（Day1/Day2）
- ❌ 多行程管理 / 行程重命名 / 行程分享链接
- ❌ 小红书笔记自动抓取（口径不变）

> ⚠️ T1 里"路线规划先不走"仍然有效；本次只做**顺序 + 行程单**，
> 若用户要连线/里程，另开 T3 接高德路径规划 API。
