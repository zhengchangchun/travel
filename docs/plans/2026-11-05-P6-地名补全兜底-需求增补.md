- 日期：2026-11-05

  （实测 `USER_DAILY_QUERY_OVER_LIMIT`）⇒ 「笔记正文 → 真实地图上的点」最后一跳一直没法用真数据跑通
- 前提：P4 已把「提取地名 → 高德补全 → 地图/加入选择」做完（当时只用假高德验过）

## 1. 决定

给地名补全加一个**免 key 的兜底源**（OSM / Photon），规则：

| # | 决定 | 理由 |
|---|---|---|
| D1 | 先高德，失败/无果再 OSM；可用 `geocoder=amap\|osm\|auto` 显式指定 | 高德是国内 POI 权威，不能本末倒置 |
| D2 | 来源**逐条落库**（`note_places.source`）、界面打 `OSM` 角标、回执里分列 `calls` / `osm_calls` | 兜底数据不能被当成高德数据 |
| D3 | OSM 结果**必须同名**才认（归一后相等或互相包含，长度 ≥2）；否则报「没有同名地点」 | 实测 OSM 对「1% COFFEE」会给「环城东路」这种无关街道 —— **错点比没点更坏**（旅行规划） |
| D4 | 低频礼节：最小间隔 1.1s、单名一次、单次最多 8 个名字、带标识 UA | Photon 是公共免费服务 |
| D5 | 两个源都失败才报错，且**同名合并成一条**（错因拼接） | 界面上不要重复同一名字 |
| D6 | 只做「按名字补全」，不做反向地理编码/批量铺点 | 与既有边界一致 |

## 2. 落地

- 新 `server/geocode-osm.js`：`searchOsm`（Photon `/api/?q=<名字 城市>&limit=N`）、
  `normalizeFeature`（→ 与高德同形状的 POI：`id='osm:type+id'`、`source:'osm'`、无评分不编）、
  `matchesName` / `normName`、`MIN_INTERVAL_MS=1100`。
- `note_places` 加 `source` 列（`ensureColumn` 前滚）；插入/读回都带它。
- 路由 `POST /api/notes/:id/places`：高德 → OSM 兜底 → 都没有则留空；返回加
  `osm_calls` / `by_source`；`createApp({osm})` 可注入（**单测一律注入假 OSM，不许真联网**）。
- 页面：地点行加 `OSM` 小角标；回执显示「高德 N 次 · OSM 兜底 M 次 · 补全成功 K 个」；
  **顺手修一个真 bug**：地名输入原来按空白切分，会把「1% COFFEE 精选店」切成三个碎片 ⇒ 改成只按顿号/逗号/换行切。
- 抓取侧小补：抖音搜索页实测是**验证码中间页**（风控）⇒ 现在如实返回
  `NEED_CAPTCHA 抖音只能给链接抓单条，不能按关键词搜`（不再是一句含糊的「未实现」）。

## 4. 边界

- OSM 中文 POI 覆盖**远不如高德**（小店基本查不到），所以它只是**配额用完时的兜底**，不是替代；
  国内地名/景点/街道级能补，咖啡店/餐厅级多数补不出来 —— 这也如实反映在「补全成功 K 个」上。
- Photon 是公共免费服务：只按 D4 低频用，**不做批量/并发轰炸**。
- 高德配额 12/1 恢复后，同一条链路会自动优先走高德（无需改配置）。
