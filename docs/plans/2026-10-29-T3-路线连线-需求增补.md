# T3 需求增补：路线连线 · 里程 · 耗时

> 2026-10-29 · 依据用户原话：「乙」（＝要连线/里程/耗时）＋「步行 公交 驾车都要」
> 本文是 T1/T2 需求文档的增补。前置：T1（骨架）＋ T2（选中/我的选择/行程规划）已交付。

---

## §0 背景

T2 交付后，行程只有**顺序**（A→B→C 的清单），地图上只是几个孤立的旗子，看不出"怎么走、多远、多久"。

用户要：**把行程顺序变成可见的路线，并给出总里程与总耗时**，且**步行 / 公交 / 驾车三种都要**。

---

## §1 功能（本期做）

| 编号 | 功能 | 说明 |
|---|---|---|
| **H1** | **路线连线** | 按行程顺序把已选点两两连成路线，在地图上画出**真实路网折线**（非直线） |
| **H2** | **三种出行方式** | 步行 / 公交 / 驾车，可切换；切换后线型、颜色、里程、耗时全部随之更新 |
| **H3** | **里程与耗时** | 侧栏显示**总里程**＋**总耗时**，并列出**分段明细**（第 1 段 A→B：3.2km / 12 分钟） |
| **H4** | **分段可视化** | 地图上每一段独立成线（颜色随方式），可点选某段查看明细 |
| **H5** | **失败降级** | 某段无法规划（如步行超 100km、公交未覆盖）→ 该段用虚线直线代替 + 明确标注「无法规划」，**不崩、不阻塞其余段** |

### 交互

```
行程视图（T2）→ 顶部出现「出行方式」三选：步行 / 驾车 / 公交
   → 选一种 → 地图自动按顺序画线 + 侧栏出总里程/总耗时/分段明细
   → 切换方式 → 全部重算
   → 调整行程顺序（↑↓）→ 路线自动重算
```

## §2 数据来源（高德路径规划 REST API）

| 方式 | 接口 | 关键字段 | 注意 |
|---|---|---|---|
| 步行 | `GET /v3/direction/walking` | `route.paths[0].{distance,duration,steps[].polyline}` | **单次上限 100km** |
| 驾车 | `GET /v3/direction/driving` | 同上 | 可选 `strategy`（默认速度优先） |
| 公交 | `GET /v3/direction/transit/integrated` | `route.transits[].{duration,distance,segments[]}` | **`city` 必填**；折线要从 `segments` 里的 walking/buslines 拼 |

- `polyline` 是高德格式字符串：`"lng,lat;lng,lat;…"` → 必须解析成坐标数组
- 每对起终点**一次请求**；N 个点 ⇒ N−1 次请求 ⇒ **必须串行 + 间隔**（避免 QPS 限流）
- 全部结果**走缓存**（键含 mode + origin + destination），避免重复消耗配额
- 三种方式的 `duration` 单位是**秒**，`distance` 单位是**米**

## §3 接口契约（在 T1/T2 基础上新增）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/route?mode=&origin=lng,lat&destination=lng,lat&city=` | 单段路线：`{mode,distance,duration,polyline:[[lng,lat],…],steps:[{instruction,distance,duration,polyline}],transit:{…}\|null,degraded:false}` |
| GET | `/api/itinerary/route?city=&mode=` | **整条行程**：按该城行程顺序逐段规划，返回 `{mode,legs:[{from,to,distance,duration,polyline,ok,degraded}],totalDistance,totalDuration,failed:[{index,reason}]}` |

- `mode` 取值：`walking` / `driving` / `transit`；非法值 → `400`
- 某段规划失败：该段 `ok:false` + `degraded:true`，`reason` 写明（如 `步行距离超过上限`），**HTTP 仍 200**（部分成功也算成功）
- 整条路线若**一段都规划不出** → `502`
- 行程点数 < 2 → `400`（没什么可连的）

## §4 交互与视觉

- **出行方式切换**：三个 chip（🚶 步行 / 🚌 公交 / 🚗 驾车），单选，**默认驾车**
- **线型区分**（一眼可辨）：
  - 驾车＝蓝色实线（较粗）
  - 步行＝绿色点线
  - 公交＝橙色虚线
- **分段着色**：每段独立 Polyline，点击弹出该段明细
- **侧栏路线面板**：
  ```
  出行方式：🚗 驾车
  总里程：12.4 km      总耗时：38 分钟
  ─────────────
  ① 酒店 → 西湖      3.2 km / 12 min
  ② 西湖 → 楼外楼    1.8 km /  8 min
  ③ 楼外楼 → 灵隐寺  7.4 km / 18 min
  ```
- **加载态**：多段规划要逐段请求，必须显示进度（如「正在规划 2/5 段…」），不能白屏
- **失败段**：灰色虚线 + 「⚠ 无法规划（原因）」

## §6 对既有实现的影响

- **不改** T1/T2 的数据模型（路线**不落库**，每次实时算 + 内存缓存）
  - 理由：路线是派生数据，落库会带来失效问题；缓存足以。
  - 若后续要"保存路线快照"另开任务。
- `server/amap.js` 需扩展三个路径规划封装（复用现有 `amapGet`）
- 前端新增 `web/js/route.js`（连线、方式切换、总览渲染）
