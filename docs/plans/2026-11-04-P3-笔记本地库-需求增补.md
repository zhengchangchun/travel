# P3 笔记本地库（需求增补）：笔记换成内容源，下载缓存到本地，之后从本地读

日期：2026-11-04　分支：main　前置：`2026-11-04-P2-账本补采-需求增补.md`

用户口径（原话）：「**先不做到处插小旗，先做按照笔记搜索地方，笔记区分来源，下载后缓存到本地，之后从我这读取**」

## §1 先做的技术调研：平台侧抓不到（结论要留档，别重复试）

| 尝试 | 结果 |
|---|---|
| 免登 curl 抓搜索页 | B站 → 返回风控 HTML（非 JSON）；微博 → 302 到 `passport.weibo.com/visitor`；抖音 → 200 但纯 SPA 壳（2 个 script、无 `RENDER_DATA`/`aweme_list`）；小红书 `/explore` → 302 |
| OG 标签（换微信 UA 走「分享给微信」的服务端渲染） | 抖音 72914 B 壳、**无任何 og: 标签**；小红书直接 302 |
| **带登录态**（`tools/browser/pw.cjs --profile douyin` + Playwright） | 抖音 → 标题「**验证码中间页**」（识别自动化）；小红书 → `error_code=**300012** 当前网络存在风险`（IP 风控，同 aTrust VPN 历史问题） |

⇒ **本机自动抓取这条路不通**。口径因此定为：**内容由用户提供，本层只负责落库/落图/本地读**，不写假的「自动抓取」。

## §2 落地方案

### 表（`notes`，ensureColumn 幂等前滚）
新增 `source_type` / `author` / `content` / `cover` / `images` / `tags` / `fetched_at`。
- 库里 `cover`/`images` 存**本地文件名**，对外统一暴露成 `/notes-img/<file>`。

### 新接口
| 接口 | 作用 |
|---|---|
| `GET /api/notes/search?q=&source=&city=&limit=` | 本地搜索：`q` 命中标题/正文/作者；`source` 同时认 `source`（小红书）与 `source_type`（xhs） |
| `POST /api/notes`（扩展） | 接受 `content/author/source_type/tags/image_urls/cover`；`image_urls` 会**下载到本地** |
| `PATCH /api/notes/:id`（新） | 给已有笔记补正文/作者/图（用户手给内容时走这条） |
| `GET /notes-img/<file>`（新静态路由） | 从 `data/notes-img/` 出图（环境变量 `TRAVEL_NOTE_IMG_DIR` 可重定向，测试用） |

### 图片下载（`server/note-images.js`）
- 命名 = `sha1(url)[:16] + 扩展名`（按 content-type 判扩展、兜底看 URL 后缀）
- **幂等**：同 URL 已有文件直接复用，不再打图源
- 带 `Referer`（同源）以应对防盗链；单张失败不影响其余，逐张回报 `{ok,error}`
- 回复里图片明细放 `download` 键（**不覆盖** `images` 那个 URL 数组）
