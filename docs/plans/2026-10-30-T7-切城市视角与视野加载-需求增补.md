# T7 需求增补：切城市视角与视野加载

> 2026-10-30 · 依据用户原话：「切换城市的话默认会切换到城市的**主城区**，然后地图**放大到一个合适的倍率**后
> **再开始加载地图上的信息**」
> 前置：T1–T5 已交付。

---

## §0 背景与现状

**现状**（代码核查）：

- `web/js/app.js::loadCityPois(city)` → `API.listPois({city, limit: 5000})`，**一次拉全城已收录点**（杭州 12786 条）
- `web/js/map.js` **没有** `moveend`/`zoomend`/`getBounds` 处理 ⇒ 地图**不会跟随视野加载**
- 切城市时没有明确的「先定位到主城区 + 设定倍率」这一步

**用户要的**：切城市 → 落到**主城区** → 放大到**合适倍率** → **然后**才加载地图上的信息。

**实测（主城区怎么取）**：高德 `config/district` 返回的城市 `center` **就是主城区**，逐城验证：

| 城市 | 高德 center | 逆地理编码落到 |
|---|---|---|
| 北京 | 116.405285,39.904989 | 东城区（天安门一带）|
| 上海 | 121.472644,31.231706 | 黄浦区（人民广场）|
| 成都 | 104.066301,30.572961 | 青羊区（天府广场）|
| 杭州 | 120.209903,30.246566 | **上城区钱江新城市民中心（市政府）** |

⇒ **直接用高德返回的 `center`，不自己猜**。

## §1 功能

| 编号 | 功能 | 说明 |
|---|---|---|
| **M1** | **切城市落主城区** | 用 `GET /api/city/search` 返回的 `center` 作为中心；**不要**用整城包围盒 `fitBounds`（会拉太远） |
| **M2** | **合适倍率** | 常量 `CITY_ZOOM`（默认 **13**，可配）；切城后 `setZoomAndCenter(CITY_ZOOM, center)` |
| **M3** | **先定位、后加载**（顺序硬要求） | 流程＝清旧旗 → 飞到主城区/倍率 → **等 `moveend`** → 才请求 POI。禁止「先拉全城再飞」 |
| **M4** | **视野加载** | 地图 `moveend`/`zoomend` → **防抖 300ms** → 取 `getBounds()` → 拉该视野的 POI → 落旗 + 刷列表 |
| **M5** | **竞态处理** | 只接受**最后一次**请求的响应（用递增序号丢弃过期响应），快速拖动不许出现错乱 |
| **M6** | **双口径计数** | 同时显示「**当前视野 N 条** · 全城已收录 M 条」，避免用户以为数据丢了 |
| **M7** | **过密保护** | 视野内点过多（阈值常量，默认 **800**）→ 自动抽稀或提示「放大以查看更细」；不许卡死 |

## §2 接口变更

`GET /api/pois` 增加 **`bbox`** 参数（与 `city` / `category` / `minRating` / `sort` / `limit` / `offset` 可叠加）：

```
GET /api/pois?city=杭州&category=stay&bbox=120.10,30.20,120.30,30.30&limit=2000
```

- `bbox` 格式：`minLng,minLat,maxLng,maxLat`（左下、右上）
- 返回点**必须**落在 bbox 内（`lng BETWEEN minLng AND maxLng` 且 `lat BETWEEN minLat AND maxLat`）
- 格式非法 → `400`
- 与 `sort=rating`、`minRating` 可同时使用

> 仍**只读缓存**，不打高德（配额保护不变）。

## §3 交互细节

```
选城市（或搜索城市）
   → 清空现有旗子
   → 地图飞到「该城 center」+ zoom=13
   → moveend 触发 → 取 bbox → GET /api/pois?...&bbox=...
   → 落旗 + 左侧列表刷新 + 计数显示「当前视野 N · 全城 M」
拖/缩地图
   → 防抖 300ms → 同上（后半段）
```

- 切城市时**要给出「定位中…」的状态提示**，别让用户以为卡住
- 视野请求进行中显示轻量 loading，不阻塞交互

## §4 不做

- ❌ 不做服务端瓦片/矢量切片（本地小工具不需要）
- ❌ 不做自适应倍率的高深算法（固定 13 起，用户自己缩放）
- ❌ 不改采集逻辑（T4 已定）
- ❌ 不改主城区判定为「按 POI 密度聚类」（高德 center 已够准）
