## §0 背景

用户要「看好评」。实测结论（见需求增补 §0）：**高德 API 不给评价文本**（`featured_reviews` 恒空），
但**给评分、用户实拍图、招牌菜标签**，且能跳 `amap.com/detail/<id>` 看真实评价。

所以本期做的是：**把能拿到的做成一个像样的详情面板 + 一个直达按钮**，并**诚实标注**评价正文的缺口。

## §2 T1 · 后端：单点详情接口

- `GET /api/pois/:poiId` → 从 T4 的 `pois` 表读；不存在 → `404`
- 返回 `photos` 每项：`{url, isComment, source:"amap"}`（`isComment` = url 含 `aos-comment`）
- 返回 `tags`：由采集存下的 `atag` 拆成数组（按 `,` 切、去空、去重、最多 12 个）
- 返回 `amapUrl`：`https://www.amap.com/detail/<poi_id>`（后端拼）
- 找不到该点（例如从实时搜索来的、没进缓存的）→ **回退**：用高德 `place/detail` 现取一次并返回（**不落库**）

## §3 T2 · 前端：详情面板

- 把 T2 的「信息卡」升级为**详情面板**（**合并，不要并存两套**）：
  - **图集**：`photos` 全部图片，可左右翻；评论实拍图**优先**且带「用户实拍」角标
  - 评分/人均/电话/营业时间；详细地址（可复制）
  - **招牌菜标签**：一排 chip
  - **满分金色徽章**（沿用 T4 的 `TOP_RATING` 规则）
  - 按钮：`[导航]` `[去高德看评价]`（新窗口打开 `amapUrl`）`[去小红书看笔记]` `[加入行程 ★]`
- **诚实标注**：面板底部一行小字「高德接口不提供评价正文，点『去高德看评价』看真实评价」
- 图集图片加载失败要有占位，不能破图
- 窄屏（375px）下详情面板仍可用
