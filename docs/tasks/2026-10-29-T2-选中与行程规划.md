## §2 T1 · 后端：选中模型与接口

- `server/db.js`：幂等迁移（`ALTER TABLE pins ADD COLUMN sort_order INTEGER NOT NULL DEFAULT 0`）＋ 索引 `idx_pins_poi`
- 新增查询：`getSelectionByCity(city)`（JOIN trips 按城市取 pins，按 `sort_order, id` 升序）、
  `getOrCreateCityTrip(city)`、`insertPinIfAbsent(city, poi)`（按 `(city, poi_id)` 幂等）、
  `deletePinByPoi(city, poiId)`、`reorderPins(city, poiIds)`、`buildItineraryMarkdown(city)`
- `server/routes/selection.js` 实现 §3 的 5 个端点（见需求增补 §3）
- 参数校验：`city` 必填；`poi` 缺 `id/name/lng/lat` → `400`；不存在的 poi_id 取消 → `404`

## §4 T3 · 前端：只看选中的 + 行程视图

- **「只看我选中的」开关**：开启后地图与主列表只保留已选点；**与分类 chip 可叠加**
- **「规划行程」按钮** → 左侧切到行程视图：
  - 已选点按 `sort_order` 列出，带序号
  - 每行 **↑ / ↓** 调整顺序（最低要求；拖拽可选）→ 调用 `PUT /api/selection/order`
  - 顺序**刷新后仍保持**（持久化验证）
  - 按分类分组展示（住宿/美食/景点/游玩）
- **行程单**：`一键复制` + `下载 .md`（走 `/api/selection/export?city=&format=md`）
- **修 T1 遗留**：底部状态栏计数随过滤实时刷新（T1 §8.3-3）
